# depgraph — визуализатор графа зависимостей (вариант 17, pip)

## Общее описание

Консольный инструмент для анализа зависимостей Python-пакетов (формат
pip): строит граф зависимостей пакета и выводит его на языке диаграмм
PlantUML. Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются (pip и pipdeptree запускаются только для
сравнения результатов).

**Реализованы все этапы 1–5.**

## Параметры конфигурации (YAML)

| Параметр       | Обязателен | Описание                                             |
|----------------|------------|------------------------------------------------------|
| `package_name` | да         | имя анализируемого пакета                            |
| `repository`   | да         | URL репозитория (корень JSON API, напр. `https://pypi.org/pypi`) или путь к файлу тестового репозитория |
| `test_mode`    | нет        | `true` — `repository` это файл; по умолчанию `false`  |
| `filter`       | нет        | подстрока: пакеты с ней в имени не анализируются (без учёта регистра) |

## Режимы работы

`run.bat --config PATH [--mode MODE] [--output FILE]`

| Режим      | Что делает                                              |
|------------|---------------------------------------------------------|
| `graph`    | транзитивный граф, статистика, циклы (по умолчанию)      |
| `order`    | порядок загрузки (зависимости раньше зависимых)          |
| `plantuml` | диаграмма на языке PlantUML (печатается на экран)        |

`--output FILE` дополнительно сохраняет текст PlantUML в файл (UTF-8).

## Как это работает

- **Данные.** `<repository>/<имя>/json` (PyPI JSON API через `urllib`),
  имена прямых зависимостей из `requires_dist`; необязательные (`extra`)
  пропускаются, версии и условия среды игнорируются.
- **Граф.** BFS с очередью, без рекурсии; циклы не зацикливают обход.
  Пакеты с подстрокой `filter` в имени не анализируются.
- **Порядок загрузки.** Обход в глубину с явным стеком, пакет
  записывается после всех своих зависимостей; ребро, замыкающее цикл,
  игнорируется.
- **PlantUML.** Каждый пакет — прямоугольник с псевдонимом `n0`, `n1`…
  (корневой пакет выделен цветом), каждая зависимость — стрелка.
- **Тестовый репозиторий.** `test_mode: true`, файл со строками
  `A: B C` (имена — заглавные латинские буквы), примеры в
  `examples\repos`.

### Как отрисовать диаграмму

Вставьте текст в https://www.plantuml.com/plantuml или откройте `.puml`
в VS Code с расширением PlantUML. Готовые примеры:
`examples\plantuml`.

## Сравнение с настоящими инструментами

```
python -m src.compare --config configs\requests.yaml              (порядок, pip)
python -m src.compare --config configs\requests.yaml --what graph (граф, pipdeptree)
```

Команды создают временное виртуальное окружение, ставят в него пакет
(`pip install`), а для графа ещё `pipdeptree`, и сравнивают результат с
нашим. Параметр `--saved FILE` берёт сохранённый вывод (текст pip или
JSON `pipdeptree --json -p пакет`) вместо запуска.

Сравнение графа показывает пакеты и связи, которые есть только у нас
или только у pipdeptree.

### Почему результаты могут расходиться

1. **Версии.** Мы берём метаданные последней версии и игнорируем
   ограничения версий; pipdeptree показывает фактически установленные
   версии, подобранные pip.
2. **Условия среды.** Мы не вычисляем `python_version`, `sys_platform`;
   pipdeptree показывает только то, что реально установлено на вашей ОС
   и версии Python. Поэтому у нас могут быть лишние пакеты (например,
   `colorama`, `importlib-metadata`).
3. **Необязательные зависимости (extras)** мы пропускаем; pipdeptree
   их не показывает, если они не установлены.
4. **Форма вывода.** pipdeptree по умолчанию печатает дерево, где общие
   пакеты повторяются, а мы строим граф, где каждый пакет один раз;
   сравнение идёт по множествам пакетов и связей.
5. **Фильтр.** При заданном `filter` в нашем графе этих пакетов нет.

Результаты своих запусков (три пакета) запиши в отчёт для защиты.

## Установка, запуск и тесты

```
pip install -r requirements.txt
run.bat --config configs\test_cyclic.yaml --mode plantuml
python -m unittest discover -v
scripts\demo_stage5.bat
```

Тесты не требуют интернета. `scripts\demo_stage5.bat` для реальных
пакетов требует интернет; диаграммы сохраняет в папку `out`.

## Пример

```
> run.bat --config configs\test_simple.yaml --mode plantuml
@startuml
title Dependency graph of A
rectangle "A" as n0 #LightBlue
rectangle "B" as n1
rectangle "C" as n2
rectangle "D" as n3
n0 --> n1
n0 --> n2
n1 --> n3
n2 --> n3
@enduml
```
