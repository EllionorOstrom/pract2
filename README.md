# depgraph — визуализатор графа зависимостей (вариант 17, pip)

## Общее описание

Консольный инструмент для анализа зависимостей Python-пакетов (формат
pip). Конечная цель работы — построить граф зависимостей пакета и
вывести его на языке PlantUML. Готовые менеджеры пакетов и библиотеки
для получения зависимостей не используются.

**Реализованы этапы 1–4**: конфигурация, получение зависимостей,
граф (BFS, фильтр, циклы, тестовый режим), порядок загрузки.

## Параметры конфигурации (YAML)

| Параметр       | Обязателен | Описание                                             |
|----------------|------------|------------------------------------------------------|
| `package_name` | да         | имя анализируемого пакета                            |
| `repository`   | да         | URL репозитория (корень JSON API, напр. `https://pypi.org/pypi`) или путь к файлу тестового репозитория |
| `test_mode`    | нет        | `true` — `repository` это файл; по умолчанию `false`  |
| `filter`       | нет        | подстрока: пакеты с ней в имени не анализируются (без учёта регистра) |

## Режимы работы

`run.bat --config PATH --mode MODE`

- `graph` (по умолчанию) — транзитивный граф (этап 3);
- `order` — порядок загрузки: зависимости раньше зависимых пакетов.

Данные, граф (BFS без рекурсии), фильтр, циклы и тестовый репозиторий
работают как на этапе 3 (формат тестового файла: `A: B C`, имена —
заглавные латинские буквы).

## Порядок загрузки

Обход графа в глубину с явным стеком; пакет записывается в результат,
когда обработаны все его зависимости (обратный порядок обхода,
topological sort). Ребро, замыкающее цикл, игнорируется, поэтому
порядок внутри цикла произвольный; программа сообщает о цикле.

## Сравнение с pip

```
python -m src.compare --config configs\requests.yaml
python -m src.compare --config configs\requests.yaml --saved pip_output.txt
```

Команда создаёт временное виртуальное окружение, ставит в него пакет
настоящим `pip install` и берёт из его вывода строку
`Installing collected packages: ...` — это реальный порядок установки.
Затем сравнивает с нашим порядком: пакеты только у нас / только у pip,
одинаковый ли порядок общих пакетов, нарушает ли порядок pip зависимости
нашего графа. `--saved` берёт текст вывода pip из файла вместо запуска.

(`pip install --dry-run` для этого не подходит: он печатает пакеты
в алфавитном порядке.)

### Почему результаты могут расходиться

1. **Версии.** Мы берём зависимости последней версии пакета и
   игнорируем ограничения версий; pip решает, какие версии подходят,
   и может взять другие.
2. **Условия среды.** Мы не вычисляем `python_version`,
   `sys_platform` и т. п., считая такие зависимости прямыми. pip
   учитывает вашу ОС и версию Python (например, `colorama` ставится
   только в Windows), поэтому у нас может быть лишний пакет, а у pip —
   нет.
3. **Уже установленные пакеты.** pip не переустанавливает то, что есть
   в окружении (`pip`, `setuptools` в новом окружении), в его списке их
   нет.
4. **Неоднозначность порядка.** Независимых пакетов много, допустимых
   порядков несколько; мы идём по зависимостям в порядке `requires_dist`,
   pip — по своему алгоритму. Расхождение порядка допустимо, если порядок
   pip не нарушает зависимости (программа это проверяет).
5. **Циклы.** В цикле «правильного» порядка не существует.
6. **Фильтр.** Если задан `filter`, в нашем результате этих пакетов нет,
   а pip их устанавливает.

Результаты своих запусков (requests, flask) запиши в отчёт для защиты.

## Установка, запуск и тесты

```
pip install -r requirements.txt
run.bat --config configs\test_simple.yaml --mode order
python -m unittest discover -v
scripts\demo_stage4.bat
```

Тесты не требуют интернета.
